# 众包 BLE 静态定位

## 实地验证准备与软件复核

本阶段交付安卓采集 APK、试验与测绘格式、原题核对、数据导入、校准与评估程序。当前完成了软件验证，真实众包定位结果待现场采集。两份既有公开数据仍只支持固定设施场景的结论。

## 原题核对

老师提供的《HarmonyOS难题发布-第七期》第 1 页把上报者定义为扫描丢失设备 BLE 广播并协助上报位置的附近设备。优化变量是目标二维坐标，输入包含上报位置和 RSSI 推算距离，权重可参考定位时间、定位方式、精度和置信度。

静态目标原文为“CEP90 30米以内（10个以上好心人）”。该页未把人数明确写成“至少11”，也未指定真值测绘、重复扫描、采集窗或无输出口径。本轮按任务要求安排至少11台实体手机，保留有效人数≥10和≥11两种统计。每台手机每窗计一次，目标不计入。

目标真值由独立人员用 RTK、全站仪或控制点测量登记。报告手机实际位置同时测绘，可用同一批真实 RSSI 比较系统上报坐标与测绘坐标。测绘方法和水平不确定度随点保存。

## 采集和现场方案

手机登记独立编号和安装 UUID，并记录型号、Android 版本、WGS84 经纬度、定位提供者、水平精度、RSSI、时间戳和目标 UUID。App 支持独立目标手机广播，报告手机按采集票扫描。本机按活动保存原始记录，经 Android 文件选择器导出。统一 JSON 接口也接受其他工具按相同协议采集的记录。

现场建议准备13–15台上报手机及单独目标，保证至少11台参与。先在独立预演位置检查定位、BLE、导出和设备间时钟。正式场地覆盖不同方向、距离、遮挡和布局。建议12个校准、6个开发、8个验证、至少20个最终目标物理位置，重复窗留在同一分区。

每个窗建议30秒。目标和手机在窗内静止。每个报告手机对应独立测绘标记。计划先登记全部试验和手机名单，随后按票采集。漏报、失败和无输出继续保留在预定分母。

## 评估与研究闭环

每台手机的目标包用当时最新的非模拟定位匹配，位置年龄最多5秒。保留目标包可见手机数与具备有效坐标的手机数。报告坐标和 RSSI 各取配对中位数。源经纬度投影到共同的局部东/北坐标系。

冻结 Cauchy+MAD 与 WLS、报告坐标中心比较。校准对照包括固定先验、统一参数、逐手机截距和共享斜率。独立校准只使用该分区测绘距离。正式定位只用手机上报坐标与 RSSI。测绘接收坐标对照单独用于离线诊断。

定位误差按物理位置等权。≥10与≥11分别给出有输出 CEP90、输出覆盖率与把无输出计入的总体成功率。全体预定试验另报告同时满足人数和30米的比例。还按实测手机位置误差、有效人数、型号和几何分组。

现有 proposer 只看开发及验证结果。独立 verifier 用≥11有效手机的成对验证窗裁决，每轮保留实际退化和丢失输出。候选、拟合和源码锁定后才评价最终数据。审计重拟合、复算裁决、复放输出并检查位置分区。

## 待现场验证

构建环境的 ADB 未连接手机。首轮现场验收需实机安装，确认权限、目标广播、同步扫描、实测定位和导出正常。随后由至少11台独立手机与独立测绘完成正式采集。

真实有效上报数、CEP90、覆盖率、硬件差异和坐标误差影响均待测。当前没有真实数据触发算法变更。合成夹具的裁决仅验证管线，不提供原题达标证据。
